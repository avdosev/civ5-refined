# Локальный визуализатор штатного TechTree

## Проверка путей v13

`geometry.py` связывает каждый сегмент с фактическим стеком исполнения Lua: строкой зависимости или владельцем штатного адаптера. Для проверки непрерывности используются альфа-маски сегментов конкретной зависимости: чужие карточки вырезаются, затем проверяется достижимость входного порта от выходного. Отдельная проверка ищет непрозрачные пиксели линии внутри чужой карточки; прозрачный прямоугольник спрайта пересечением не считается. С исходными DDS используются их маски; без них результат относится к обозначенной реконструкции текстур.

`tests/native_tree.py` сохраняет старые дефекты режима `stock`, а затем требует ноль разрывов и скрытых карточками линий для игрового контроллера мода. Проверяются вертикали в обе стороны на 1/3/4/5/9 строк, протокол выбора исследования и бесплатной технологии, состояния карточки, кража технологии и запрет науки. Это проверки с моделью API; загрузку VFS и кнопки в настоящей BNW проверяют отдельно.

Этот инструмент создан 8 ноября 2026 после неудачной раскладки v12. Он **исполняет игровой `TechTree.lua` под Lua 5.1**, записывает создаваемые UI-элементы и выводит их. По умолчанию это текущие `mod/UI/TechTree.lua` и `RefinedTechTreePipes.lua`, входящие в установочный пакет; `--renderer stock` исполняет неизменённый внешний контроллер для сравнения и регрессий. Алгоритм соединений не переписан на Python. Отсутствующие сегменты, пересечения и несовпадающие адаптеры не исправляются композитором превью.

Старая `dev-utils/tech-tree.html` остаётся справочником зависимостей. Её плавные линии не служат проверкой игрового интерфейса.

## Запуск

Из корня репозитория, Python 3.9+:

```sh
python3 -m venv /tmp/refined-tree-venv
/tmp/refined-tree-venv/bin/pip install -r dev-utils/native-tree-requirements.txt
/tmp/refined-tree-venv/bin/python dev-utils/native_tech_tree.py --fetch-references
```

`--fetch-references` нужен только при первом запуске. Он скачивает файлы с закреплённых коммитов, проверяет SHA-256 и сохраняет их в игнорируемый `dev-utils/.cache/native-tree/`. Последующие запуски работают без интернета. Результат — **`dist/native-tree/index.html`**, автономная страница с изображением внутри, а также `scene.png`, `late.png`, `controls.json` и `trace.json`.

Для работы с автоматическим обновлением:

```sh
/tmp/refined-tree-venv/bin/python dev-utils/native_tech_tree.py --serve --watch
```

Откройте `http://127.0.0.1:8765/index.html`. При изменении SQL/XML/UI Lua мода или файлов внешнего UI инструмент заново создаёт БД, применяет правки, исполняет Lua и обновляет страницу. Ошибка SQL показывается в странице и консоли, а не выдаётся за успешное превью. Сервер слушает только loopback. Смена Python-кода инструмента требует перезапуска процесса.

В странице есть поиск, масштаб, прокрутка и выбор карточки с её фактическими координатами. Родители или потомки подсвечиваются голубым: это маски реально созданных спрайтов. Можно выбрать непосредственные связи или всю цепочку, вписать путь в экран, перейти по кнопке родителя/потомка и показать границы спрайтов. Разрывы остаются видимыми; рядом перечисляются замечания. Выбор технологии сохраняется после автоматического обновления. Полные записи контролов доступны в `trace.json`; хеши SQL и UI позволяют установить, какие именно файлы визуализировались.

## Откуда берутся данные и геометрия

1. Полная чистая база BNW копируется в память; исходный файл открыт только для чтения.
2. Порядок действий XML/SQL читается из реального списка сборщика `tools/build.py`. В отличие от старой схемы, исполняется весь стек, включая контент и назначения иконок.
3. Исходные XML-описания `TechButtonInstance`, `TechPipeInstance`, `EraBlockInstance` создают контролы для окружения Lua.
4. Выполняются выбранный игровой контроллер и внешний `TechButtonInclude.lua`. В режиме `stock` выполняется весь неизменённый внешний `TechTree.lua`. В режиме `mod` исполняются ровно два Lua-файла из игрового пакета, без отдельной версии алгоритма для превью.
5. API-рекордер сохраняет `SetOffsetVal`, размеры, текстуру, `TextureOffset`, скрытие элементов, текст и портреты. Создание экземпляров, геометрия карточек/сегментов и выбор значков происходят в исходном Lua. Неизвестные методы API завершают выполнение ошибкой вместо молчаливой заглушки.
6. Локальный композитор использует якоря XML и записанные свойства. Он не знает, какие технологии нужно соединить: каждый спрайт рисуется и обрезается в своём собственном прямоугольнике. Поэтому разрыв не заполняется «правильной» линией.

Исследования моделируются явно через `--researched TECH_AGRICULTURE ...`, по умолчанию команда ничего не изучила. `--civilization CIVILIZATION_RUSSIA` выбирает цивилизацию для штатного отбора уникальных юнитов/зданий; по умолчанию Америка. Это не чтение сохранения и не симуляция экономики или ИИ. Подробные подсказки юнитов/зданий сокращены до названий, а не вычислены движком по состоянию города.

## Проверка текущих и экспериментальных правок

По умолчанию визуализируются текущие файлы мода. Чтобы посмотреть прежний этап или дополнительный SQL, не меняя игровую сборку:

```sh
python dev-utils/native_tech_tree.py --stage stock --renderer stock --output dist/native-stock
python dev-utils/native_tech_tree.py --stage Modernization --output dist/native-before-presentation
python dev-utils/native_tech_tree.py --sql /tmp/layout-experiment.sql --output dist/native-experiment
```

`--sql` можно повторять. Любые экспериментальные изменения применяются только к отдельной БД в памяти. Инструмент не перепаковывает мод, не пишет в установленную игру и не меняет исходные SQL.

Полная фактическая БД уже загруженной партии тоже поддерживается:

```sh
python dev-utils/native_tech_tree.py --database /path/to/Civ5DebugDatabase.db --loaded-database
```

При `--loaded-database` миграции не выполняются повторно. Без этого флага принимается только чистая база из 81 технологии. Это два явно разных режима, исключающих повторное смещение колонок.

## Точность и внешние файлы

**Геометрия:** выбранный игровой Lua создаёт каждую карточку и каждый кусок соединения. Сохраняются реальные величины, порядок создания, обрезка спрайтов, размеры эпох и их размещение в горизонтальном стеке. В режиме `stock` сохраняется и общий адаптер источника. Никакого автолэйаута и сглаживания графа в композиторе нет.

**Иконки мода:** читаются непосредственно из тех же DDS, которые входят в игровой пакет, с указанными атласом, индексом и размером.

**Оформление:** в репозитории нет оригинальных игровых DDS линий, Grid9 и стандартных портретов. По умолчанию внешний вид трёх спрайтов линий восстановлен; их прямоугольники и смещения остаются исходными. Grid9-оформление приближённое, отсутствующие штатные портреты показаны явными буквенными заглушками. Шрифт и `Locale.TruncateString` имеют локальную замену. Это нельзя называть попиксельным снимком работающего движка.

Чтобы использовать исходники и текстуры именно целевой установленной версии игры:

```sh
python dev-utils/native_tech_tree.py \
  --database /path/to/clean/Civ5DebugDatabase.db \
  --ui-dir /path/to/BNW/UI \
  --assets /path/to/extracted/BNW/textures \
  --font /path/to/UI-font.ttf
```

В `--ui-dir` должны лежать `TechTree.lua`, `TechTree.xml`, `TechButtonInclude.lua`. Для ветвей используются `TechBranchH.dds`, `TechBranchV.dds`, `TechBranches.dds`; атласы ищутся по имени файла. При наличии исходного DDS его окно с нужным `TextureOffset` читается напрямую. Шрифты, оригинальные портреты и оформление не заменяют игровой движок целиком: масштабирование ОС, анимации и движковый шейдер не проверяются здесь.

## Источники и распространение

URL, коммиты и SHA-256 закреплены в `dev-utils/native_tree/references.json`. Внешний Lua/XML — [публичное зеркало UI Civ5-Patch](https://github.com/catscatsforever/Civ5-Patch/tree/21efef205d910b6eb67905e2e9c2a9659e94e9e4/tmp/ui); данные — [снимок BNW civvapi](https://github.com/Eyefyre/civvapi/blob/09997cb58c8f8c0d424bd31e3baa71f5b6eb0bb2/Civ5DebugDatabase.db), тот же источник, что у прежних тестов проекта.

Зеркало содержит изменения FreeTech/Duel и значок числа цивилизаций, изучивших технологию; оно не объявляется побайтной копией файлов установленной у пользователя игры. Его дополнительные настройки Duel отключены в окружении. Отсутствующая в снимке таблица `Technology_FreePromotions` явно предоставлена как пустая; в моде таких строк нет. Эти оговорки записаны в выходных данных. Для сверки конкретной версии предназначен `--ui-dir`, без редактирования алгоритма визуализатором.

Внешние исходники и база кэшируются локально, **не добавляются в Git и не включаются в пакет мода**: их правообладатели и условия не заменяются MIT-лицензией этого репозитория. В Git находятся собственные рекордер, композитор, интерфейс и тесты.

## Регрессионные проверки

```sh
python tests/native_tree.py
```

Тесты исполняют внешний и игровой Lua мода и проверяют:

- создание 97 карточек и 618 спрайтов для текущего стека из 158 зависимостей;
- координаты, переданные исходным кодом в контролы, а не координаты из второго алгоритма раскладки;
- отсутствие вертикального сегмента для разницы в пять строк;
- шестипиксельный зазор между прямоугольниками вертикального участка и нижнего угла в изолированном случае четырёх строк;
- разнесённые по разным колонкам нисходящий угол и вертикальный сегмент смешанного дальнего разветвления;
- применение экспериментального SQL и отсутствие повторной миграции готовой игровой БД;
- вывод PNG из полученных контролов и чтение собственных DDS мода.

Эти проверки подтверждают работу локального инструмента и выбранных исходников. Они не подтверждают качество самой раскладки v12, которую пользователь отверг, и не превращают результат в успешную игровую пробу.
