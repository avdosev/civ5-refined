# Локальная сборка

Полное интерактивное [дерево технологий](../../dev-utils/tech-tree.html) с текущими правками открывается в браузере без сервера. Есть поиск, масштаб и подсветка зависимостей. После изменения SQL обновляйте его командой `python3 dev-utils/tech_tree.py`; [описание и источники данных](../../dev-utils/README.md).

Команды выполняются из корня репозитория.

Исходники пакета — `mod/`. Сборка готовой папки и ZIP не требует ModBuddy. Готовые DDS включены в исходники и не требуют графических библиотек для обычной сборки. После игровых миграций выполняется `SQL/Icons.sql`; DDS импортируются в VFS. Каталог выбора, исходные PNG и регенерация — в [иконках технологий, зданий и программ](../icons.md). `tests/icons.py` проверяет портреты отдельно; та же проверка включена в полный `tests/victories.py`.

Сборка и проверки:

Геометрия портретов задаётся в `assets/icons/geometry.json`: диаметры кругов и поля независимы для каждого размера DDS. `tools/icon_atlas.py` сохраняет мастера и применяет геометрию при генерации. Он также обновляет `assets/icons/fit-comparison.jpg` по мастерам, новым DDS и сохранённому пользовательскому скриншоту. Для регенерации нужен Pillow ≥11.3; обычная сборка использует готовые DDS. `tests/icons.py` проверяет диаметры, центрирование и прозрачные полосы вдоль всего края ячейки.

```sh
python3 tools/build.py
python3 tests/validate.py
python3 tests/run_lua.py --lua lua5.1
python3 tests/society.py --lua lua5.1
python3 tests/victories.py --lua lua5.1
python3 tests/victory_timing.py
```

Команды run_lua.py, society.py и victories.py требуют Lua 5.1 (можно передать путь через --lua). victories.py применяет полный стек SQL v12 к фактической проекции BNW, проверяет 97 технологий и геометрию штатных соединений, затем запускает реальные Victories.lua и Modernization.lua с моделью API. Дополнение tests/data/bnw-victories.json содержит схему и механические параметры проектов/процессов из того же публичного снимка, что bnw-society.json; это не установленная игра. victory_timing.py проверяет отдельно условную модель темпа. SQLite-проверка validate.py сохраняет проверки прежних механик на представительном наборе. Если доступна чистая игровая база:

```sh
python3 tests/validate.py --database /path/to/Civ5DebugDatabase.db
```

Файл базы открывается только для чтения; изменения проверяются на копии в памяти. Пакет создаётся в `dist/`. Концепция и текущий баланс описаны в `spec.md`; обсуждение и решения ведём в чате.

`run_lua.py` также запускает контрактные проверки диспетчера и пяти адаптеров событий. Устройство подписок, синхронных запросов и регистрации `include()` описано в [событиях Lua](events.md).

Для диагностики случая «мод включён, но контент отсутствует» выполните `python3 tools/diagnostic_build.py`. Отдельный ZIP `dist/civ5-refined (v 12) load-audit.zip` сохраняет все игровые файлы обычной сборки побайтно и добавляет независимый Lua-контекст `LoadAudit.lua`. Название пакета получает суффикс `LOAD AUDIT`. В партии через три секунды появляется одно штатное уведомление с числом технологий и наличием контрольных записей SQL; этот контекст не использует диспетчер мода, не выдаёт бонусы и не пишет в сохранение. Обычный пакет остаётся отдельно. Диагностический и обычный варианты имеют один UUID/версию, поэтому устанавливается только один из них, с полной заменой папки при закрытой игре. Файл диагностического сообщения сейчас относится к v11; перед использованием для следующей версии обновите его метку.

Финальная миграция `SQL/Presentation.sql` выполняется после всех игровых дополнений. `Text/Presentation.xml` содержит короткие описания, отдельно от точных правил в штатных значках способностей и подсказках зданий. `victories.py` дополнительно воспроизводит дальнее разветвление Электричества до исправления, проверяет строгие адаптеры после него, лимит пяти поздних карточек в колонке, военные требования и национальный Ускорительный комплекс. Промежуточные v8/v10 проверяются в прежнем режиме; итоговая v12 — с `strict_adapters=True`.
