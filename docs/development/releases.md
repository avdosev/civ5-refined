# Автоматические сборки и релизы

GitHub Actions запускает проверки SQL, дерева, локализации, пакета и Lua 5.1 на каждый push и pull request. Готовый ZIP доступен в артефакте `mod-package` на странице запуска в течение 14 дней. Workflow также можно запустить вручную через **Actions → Build and release → Run workflow**; ручной запуск только проверяет и собирает пакет.

Номер пакета хранится в `VERSION`: положительное целое число, сейчас `7`. Из него сборщик получает имя папки, ZIP и версию `.modinfo`; UUID мода сохраняется. v7 требует новой партии, минимальная совместимая версия сохранения установлена в 7. При следующем выпуске измените `VERSION`, обновите описание изменений и инструкции с номером версии, закоммитьте и отправьте изменения. После игровой пробы создайте тег на проверенном коммите:

```sh
git tag -a v7 -m 'civ5-refined v7'
git push origin v7
```

Пример предполагает `VERSION = 7`. Тег обязан точно совпадать с `v` + содержимым `VERSION`, иначе проверка остановит выпуск. Номер автоматически не повышается.

Push тега запускает все проверки и публикует **prerelease** с тем же проверенным ZIP и автоматически сформированным списком изменений. Описание содержит установку и границы автоматических проверок; добавьте к нему результат фактической игровой пробы и важные изменения для игрока. CI не запускает Civilization V и не подтверждает игровой баланс. После игровой проверки prerelease можно вручную перевести в обычный релиз.

Используется встроенный `GITHUB_TOKEN`; отдельный персональный токен не требуется. Право `contents: write` выдаётся только задаче публикации после успешных проверок. Уже опубликованный релиз workflow не перезаписывает: исправления выпускаются новым номером и тегом.
